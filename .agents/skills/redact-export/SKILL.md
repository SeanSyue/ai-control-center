# 遮蔽要交出去的檔案

AICC 本體**沒有**遮蔽功能，這是刻意的（見 `ROADMAP.md` P8）。自動遮蔽一定會漏，
把它做進匯出流程等於讓使用者以為「按了就安全了」。所以它是一個要人主動叫、
而且最後一定要人親自讀過的工具。

## 先問清楚三件事，不要猜

1. **這份要給誰看？** 內部同事、客戶本人、主管機關、還是外部廠商——
   對「什麼算敏感」的答案完全不同。給客戶本人看時，他自己的名字不用遮。
2. **哪一份檔案？** 要完整路徑。
3. **有沒有不能遮的東西？** 例如案號要留著才對得上，日期要留著才看得出時序。

## 硬規則

### 絕不就地覆蓋

一律寫成新檔，原檔不動：

```
決策紀錄_案子A_2026-08-10.md          ← 原檔，留著
決策紀錄_案子A_2026-08-10.遮蔽.md      ← 交出去的
決策紀錄_案子A_2026-08-10.對照表.md    ← 留在本機，絕不外流
```

遮蔽是不可逆的。覆蓋掉原檔等於把原始紀錄銷毀，那件事本身就違反「留紀錄」的目的。

### 對照表要另外存，而且要在檔案第一行寫明它不能外流

```markdown
> ⚠ 這份對照表不可外流。它存在的目的是讓你日後看得懂遮蔽後的文件。

| 代號 | 原文 |
|---|---|
| 客戶A | 〔真實姓名〕 |
| 機構甲 | 〔真實機構〕 |
```

### 代號要穩定

同一個人在整份文件裡永遠是「客戶A」。用隨機字串或每次不同的代號，
文件會變成讀不懂的東西，而讀不懂的紀錄等於沒有紀錄。

代號用有意義的分類：`客戶A`／`客戶B`、`機構甲`／`機構乙`、`帳號1`。
不要用 `XXX` 或 `[已遮蔽]`——那會讓「三個不同的人」看起來像「同一個人」。

### 遮蔽過的 `.jsonl` **不會**再通過雜湊鏈驗證，這是對的

決策紀錄匯出的 `.jsonl` 帶著 `prev_hash`／`hash` 雜湊鏈，
`tools/verify_decision_log.py` 靠逐字內容重算。改一個字，鏈就斷。

所以：

- 遮蔽後的 `.jsonl` 驗證會失敗。**那是正確行為，不是 bug。**
- **絕對不要為了讓它「驗得過」而重算雜湊。** 重算之後那條鏈只證明
  「遮蔽後的檔案沒被再改過」，卻長得像「原始紀錄沒被改過」。
  那是把一個誠實的檢查改造成假證據。
- 如果對方需要驗證，正確做法是**不遮蔽、走受控例外授權**（P8 已實作），
  或者只給遮蔽後的 `.md` 並明說「這份不含可驗證的鏈」。

在遮蔽後的檔案結尾附上這段：

```
本檔案經人工遮蔽處理，內容與原始紀錄不同，無法通過雜湊鏈驗證。
需要可驗證版本請另行索取。
```

## 要找什麼

先用工具掃一遍，再用眼睛讀一遍。**工具那一遍是為了不漏掉重複出現的，
眼睛那一遍是為了抓工具找不到的。**

工具找得到的：

- 中文姓名（二到四字，常出現在「客戶」「先生」「小姐」「女士」附近）
- 身分證字號、護照號碼、統一編號
- 帳號、卡號、末四碼
- 電話、Email、地址
- 金額（視情況——有時要遮，有時是重點）
- 機構名稱、公司名稱

工具找不到、只有人讀得出來的：

- **關係代稱**：「他太太」「老闆的兒子」——沒有名字，但認得的人一看就知道
- **只出現一次的識別線索**：某個很特別的職業、某個地區、某個時間點的事件
- **綽號、簡稱、內部代號**
- **可交叉比對的組合**：單獨每一項都不算個資，湊起來只指向一個人

## 收尾一定要做的兩件

1. **列出「我不確定要不要遮的」**，交給使用者判斷。不要自己決定放行。
2. **明說「這份我掃過也讀過，但自動遮蔽會漏，寄出去之前請你自己再讀一遍」。**
   這句話不是免責，是因為它是真的——只有使用者知道哪個名字是他客戶。

## 不要做的事

- 不要直接寄出、上傳、或貼到任何地方。遮蔽完就停，交給使用者。
- 不要在對話裡把原始的客戶姓名重述一遍當作「確認」——那等於把它又寫進一份紀錄。
- 不要把對照表跟遮蔽檔放進同一個壓縮檔。
