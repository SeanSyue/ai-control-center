## 為什麼這樣分模組

| 位置 | 責任 | 分開的理由／仍有的代價 |
|---|---|---|
| [`app/core/lineup.py`](../app/core/lineup.py) | 座位、供應商、職責與角色關係 | 不把「某個人的名字」寫死成權限；畫面結構與執行規則要分清楚。 |
| [`app/core/workflow_worker.py`](../app/core/workflow_worker.py)、[`steps/`](../app/core/steps/) | 串接需求、規劃、執行、驗證、複查、核准、討論 | 依功能入口拆步驟，避免改一個階段必須理解整條長函式；worker 仍負責大量流程協調。 |
| [`app/core/orchestrator.py`](../app/core/orchestrator.py) | 組裝派工、上下文與結果交接 | 集中跨步驟的協調，目前仍偏大，是保留的技術債。 |
| [`prompt_builder.py`](../app/core/prompt_builder.py)、[`rule_layers.py`](../app/core/rule_layers.py) | 提示詞與職責規則 | 讓「這個角色收到哪些要求」能單獨檢查，避免每次都發相同巨量背景。 |
| [`app/adapters/cli_runner.py`](../app/adapters/cli_runner.py) | 啟動、輸入輸出、逾時與終止 CLI 行程 | 將外部工具生命週期與產品流程分離；仍依賴 Windows 和廠商工具行為。 |
| [`app/services/`](../app/services/) | 專案登記、文件索引、驗證、紀錄、匯入與通知 | 讓持久化和外部整合有可定位入口；此層不全是純函式，路徑與權限仍須各自驗證。 |
| [`app/ui/`](../app/ui/) | Qt 視窗、狀態呈現、網頁橋接 | 介面和流程規則分開閱讀；main_window 仍有整合責任，橋接來源限制也是未解問題。 |
| [`design-pages/`](../design-pages/)、[`app/ui/web/`](../app/ui/web/) | 可編輯設計來源與產生的頁面 | 避免兩套頁面各自漂移；必須另外確認打包包含所有 assets，不能只驗來源頁面。 |

## 五個設計概念如何落地

1. **Prompt Engineering：** 以職責給任務、限制與回覆格式；可解析的回覆支援問題升級。提示詞是引導，不等於強制安全隔離。
2. **Context Engineering：** 共同記憶、必要規則和文件索引分工。規則完整性與 token 成本需要共同處理；不宣稱檢索永遠取到最佳資料。
3. **Harness Engineering：** 以官方 CLI 為執行入口，管理行程與權限參數，不另接管廠商登入。檔案權限是否生效仍依賴 CLI 與 OS。
4. **Loop Engineering：** 分清執行、驗證與修正。自動修正有上限；缺少測試或需要人決策的結果不能變成成功章。
5. **Graph Engineering：** 座位表明角色、職責與上下游呈現。`parent` 是顯示結構，實際步驟仍按順序和職責派送，討論／駁回另有規則。這不是通用 DAG 路由或任意平行排程器。

## 三個值得看程式的取捨

**把「同意」和「測量」分開。** [`approval_chain.py`](../app/services/approval_chain.py) 與相關章資料區分 machine evidence 和 review reason。理由是模型給出認可，不能取代實際指令輸出；章綁內容版本，使驗收對象明確。

**讓無法判定保留成一種結果。** [`outcomes.py`](../app/core/outcomes.py) 和驗證流程區分沒有可用驗證、未啟動、失敗、逾時與需要人處理。這比用單一成功／失敗旗標更複雜，但能避免缺證據被當成功。

**檢查測試是否真的抓得到錯。** [`negative_control.py`](../tools/negative_control.py) 會暫時破壞程式再跑指定測試。它目前缺少可靠的 baseline 前置判定，部分配方也過時；這個方法有價值，但本次數字不能說成所有規則都已被證明。

## 閱讀與重用的邊界

作者提供成功使用的陳述，公開範圍包含程式、測試和設計紀錄；不包含私人專案成果或完整外部重現材料。最新審查狀態見首頁，具體未修缺陷見 SECURITY。流程跑通與安全邊界完整，是兩件需要分開驗證的事。

本次公開整理只調整文件，沒有把已知缺陷修掉，也沒有改動模組或增加服務。保留單機桌面程式的部署形態，沒有為作品展示另加微服務或框架。
